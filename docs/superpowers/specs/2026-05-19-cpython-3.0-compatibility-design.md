# CPython 3.0.1 Compatibility — Design

**Date:** 2026-05-19
**Status:** Approved, implementation starting

## Summary

Make `python-rs` pass CPython 3.0.1.1's complete `Lib/test/` regression suite (minus an explicit, justified skip list). This becomes the first concrete compatibility milestone; modern-Python features and the Pandas track resume only after 3.0 is green.

3.0.1 is the final release in the Python 3.0 series — after 3.0.1, Python moved directly to 3.1. Pinning to 3.0.1 (rather than 3.0 final) gets us the bug fixes that landed during the 3.0 line without introducing a moving target.

The strategy is to **vendor CPython 3.0.1.1's pure-Python stdlib and test suite verbatim** and use *their* test runner (`regrtest.py`) as our progress oracle. We reimplement only the language and the minimum set of C-implemented modules that the pure-Python stdlib depends on.

## Goals

1. **Pass entire `Lib/test/`** from CPython 3.0.1 (released 2009-02-13), modulo a documented skip list for explicitly-deferred capabilities (`_ssl`, `_socket`, `_ctypes`, etc.).
2. **Frozen target.** Python 3.0 is a fixed, finite specification. We do not chase modern Python during this phase.
3. **Progress is measurable.** `compat-report.json` carries `X / N` test files passing. Number monotonically increases on `develop`/`main`; CI rejects regressions.
4. **Preserve the long-term plan.** Phase 2 (object model) continues unchanged. After 3.0 passes, work resumes on the previously planned cpyext/NumPy/Pandas track and the embedding API. (The original `AGENTS.md` doc that captured this plan has been removed; future-phase design will be re-derived into per-phase specs when those phases become active.)

## Non-Goals

- **Bytecode compatibility with CPython 3.0.1.** We keep our own bytecode (stackless, register-based, specialized opcodes). We do not load CPython `.pyc` files.
- **Drop-in CLI replacement.** Behavior parity is at the language and stdlib-API level, not at the `python3.0` binary level (no matching of exit codes, traceback formatting bytewise, or `-X` flags beyond what `regrtest` needs).
- **C extension loading during 3.0 milestone.** `cpyext`, NumPy, Pandas — deferred to Phase 4+.
- **Modern Python features.** No f-strings, walrus, match/case, async/await, type hints (syntax-only acceptance is fine if the lexer already does it; runtime support not required).
- **Threading.** Initial scope is single-threaded. `_thread` is a stub that raises on actual thread creation; threading tests go on the skip list under `c_extension_deferred` until later.

## Architecture

### Repo layout additions

```

├── Lib/                          # pure-Python stdlib — verbatim from CPython 3.0.1
│   ├── test/                     # the regression suite (our oracle)
│   └── ...                       # os.py, io.py, unittest/, etc.
├── LICENSE                       # PSF License v2, full text
├── PROVENANCE.md                 # source URL, commit hash, date, edit summary
└── patches/                      # any local modifications to vendored files
    └── README.md                 # how patches work and when they're allowed

src/cmodules/                     # Rust replacements for CPython's C-implemented modules
├── mod.rs                        # Module trait, registry, import-system hook
├── sys.rs
├── io.rs                         # _io
├── codecs.rs                     # _codecs
├── sre.rs                        # _sre — backed by the `regex` crate
├── posix.rs                      # posix (or nt.rs on Windows)

├── ...                           # one file per Tier-1/2 C module
```

### Existing code

- `src/lexer.rs`, `src/parser.rs`, `src/compiler.rs`, `src/bytecode.rs`, `src/vm.rs`, `src/object.rs`, `src/ast.rs`, `src/builtins.rs` — Phase 2 work unchanged; these continue along their existing trajectory.
- `src/main.rs` — gains a path for executing the vendored regrtest.
- `src/object.rs` — gains big-int overflow path (see Value Representation below).

## Value representation change — big int required

An earlier design assumed `int` could be NaN-boxed `i64` with no big-int support. That is not Python 3.0 compatible — Python 3 unified `int` and `long`, and `int` is arbitrary precision. The test suite exercises this (`test_long.py`, large factorials, pickling of large ints, hashes).

**New representation:**
- Small ints fit in the NaN-box payload (i48 or similar tagged form, exact size TBD in M2 spec).
- Overflow path constructs a heap `num_bigint::BigInt` and stores a tagged pointer.
- All arithmetic opcodes check for overflow and promote.
- `__hash__` for ints must match CPython 3.0.1's algorithm for tests like `test_hash` to pass.

This change has its own milestone (M2) and its own spec.

## Vendoring strategy

### What and where

- Source: CPython 3.0.1 (released 2009-02-13). Verbatim copy committed to `vendor/cpython-3.0/`. Pinned to 3.0.1 because it is the last release in the 3.0 series — frozen target, no upstream to track.
- We vendor only `Lib/` (pure-Python stdlib + tests). Not `Modules/`, `Python/`, `Objects/`, `Parser/`, `Doc/`, `PCbuild/`, `Tools/`.
- `LICENSE` (PSF License v2 text) preserved verbatim alongside.
- `PROVENANCE.md` records: source URL, commit hash or tag, fetch date, list of any edits.

### How

- Plain `git add` of a copied tree. Not a submodule. Not a subtree-merge.
- Reasoning: source is frozen, no upstream to track, repo stays self-contained, edits become legible.

### Editing policy

- Vendored files are not edited in place.
- Necessary modifications go in `vendor/cpython-3.0/patches/`, one file per logical change, each with a short rationale block at the top of the patch.
- The patch series is the entire record of where we diverge from CPython 3.0.1.

### Licensing — aggregate model

- Our code (everything outside `vendor/cpython-3.0/`): **MIT OR Apache-2.0**, no change.
- Vendored CPython: **PSF License v2** (preserved in `vendor/cpython-3.0/LICENSE`).
- Patches: derivative works under **PSF-2.0**.
- `Cargo.toml` `license` field unchanged (`MIT OR Apache-2.0`) — describes our contribution.
- README gains a short "Third-party code" section pointing at `vendor/cpython-3.0/`.

PSF-2.0 is permissive and compatible with both MIT and Apache 2.0; aggregating them in one distribution is allowed.

## C-module bootstrapping

CPython's pure-Python stdlib bottoms out in C-implemented modules. We reimplement these in Rust under `src/cmodules/`. The list is a working hypothesis; the empirical answer comes from grepping vendored `Lib/` for `import _*` once vendoring lands.

### Tier 1 — must implement (blocks the test runner itself)

| Module | Backs | Approach |
|---|---|---|
| `sys` | universal | accessors over VM state |
| `_io` | `io.py` (file objects, buffered/text wrappers) | hand impl over `std::fs` |
| `_codecs` | `str.encode` / `bytes.decode` | `encoding_rs` crate |
| `_warnings` | warnings infrastructure | minimal impl |
| `errno` | OS error number constants | generated from `libc::E*` |
| `posix` (or `nt`) | `os.py` syscalls | `libc` / `nix` |
| `_thread` | threading stubs | stub that raises on actual thread creation |
| `_sre` | `re` module | `regex` crate as engine |
| `_string` | str formatting helpers | trivial |
| `_collections` | `deque`, `OrderedDict` | back with Rust `VecDeque` + our dict |
| `_functools` | `reduce`, `partial` | trivial |
| `itertools` | iterator types | hand impl |
| `_heapq` | `heapq` | trivial |
| `time` | `time()`, `sleep()`, `strftime` | `libc` + `chrono` |
| `math` | math functions | Rust `f64` methods |
| `_random` | `random` module | `rand` / `rand_mt` |
| `_pickle` | `pickle.py` accelerators | optional — pure-Python fallback exists in 3.0 |
| `_struct` | `struct.py` | `byteorder` crate |

### Tier 2 — implement when their test files come up

`binascii`, `_hashlib` (`sha2`/`sha1`/`md-5` crates), `zlib` (`flate2`), `_bz2`, `_csv` (`csv` crate), `_datetime` (`chrono` or rely on pure-Python `datetime.py`), `_json` (optional — `serde_json` or pure-Python fallback), `_locale`, `_multibytecodec`.

### Tier 3 — stub with `ImportError`, skip dependent tests

`_socket`, `_ssl`, `_ctypes`, `select`, `signal`, `mmap`, `fcntl`, `termios`, `readline`, `_curses`, `pyexpat`, `_sqlite3`, `_tkinter`, `_multiprocessing`, `audioop`, `ossaudiodev`. Each gets a one-line skip-list entry with category `c_extension_deferred`.

### Decision rule

- Imported by `Lib/` (non-test): must at least stub, probably implement.
- Imported only by `Lib/test/`: stub OK, dependent tests skipped.
- Has pure-Python fallback in `Lib/`: can skip the C side entirely; performance cost is irrelevant for the 3.0 milestone.

## Crate policy

**Rule:** crates are allowed liberally where they reduce work or improve correctness. Hand-rolled implementations only where no good crate exists, or where the crate would bring in unacceptable transitive deps (async runtimes, large GUI stacks, etc.). Every added crate gets a one-line justification in `Cargo.toml`. (This supersedes an earlier whitelist-style policy.)

**Initial expected adds:** `num-bigint`, `regex`, `encoding_rs`, `flate2`, `sha2`, `sha1`, `md-5`, `digest`, `serde_json`, `csv`, `chrono`, `rand`, `rand_mt`, `byteorder`, `getrandom`, `unicode-normalization`, `unicode-segmentation`, `unicode-width`, `bstr`, `memchr`, `libc`, `nix`, `libloading`, `tempfile`, `dirs`, `clap`, `rustyline`, `anyhow`, `thiserror`, `criterion`, `pretty_assertions`, `insta`.

## Test harness

### Invocation

```sh
scripts/run-cpython-tests.sh             # full suite, slow
scripts/run-cpython-tests.sh --fast      # tier-1 smoke tests only, used in PR CI
```

The script sets `PYTHONPATH=vendor/cpython-3.0/Lib`, sets `PYTHONDONTWRITEBYTECODE=1`, and invokes `cargo run --release -- vendor/cpython-3.0/Lib/test/regrtest.py` with appropriate flags.

### Tier-1 smoke list (for PR CI)

`test_grammar`, `test_compile`, `test_syntax`, `test_int`, `test_str`, `test_list`, `test_dict`, `test_tuple`, `test_set`, `test_iter`. Small, stable, fast.

### Progress oracle

`tests/cpython-3.0/compat-report.json` is committed and rewritten by every full run:

```json
{
  "ran_at": "2026-05-19T00:00:00Z",
  "python_rs_commit": "...",
  "total_test_files": 0,
  "passed": 0,
  "failed": 0,
  "skipped_by_us": 0,
  "skipped_by_test": 0,
  "errored": 0,
  "by_file": { ... }
}
```

`docs/3.0-compat-progress.md` is auto-regenerated from this on every push. Headline metric `X / N (Y%)` is at the top.

### CI

- Lint, `cargo test`, and `--fast` compat run on every PR.
- Full compat run on pushes to `develop`/`main` and nightly.
- PRs that decrease the pass count fail CI. Monotonic non-regression is enforced.

## Skip-list policy

`tests/cpython-3.0/skip.toml`:

```toml
[skip.<test_name>]
category = "c_extension_deferred" | "platform_specific" | "cpython_internal" | "python_3_0_bug" | "temporary"
reason = "<short justification>"
```

`temporary` is discouraged and reviewed every milestone. Every other category is fine if the reason holds. The skip list is part of the design surface, not an escape hatch.

## Roadmap and milestones

| # | Milestone | Done when | Own spec? |
|---|---|---|---|
| **M0** | Phase 2 complete | Object model merged; `develop` green | No (in flight) |
| **M1** | Vendoring + harness | `vendor/cpython-3.0/` checked in; `scripts/run-cpython-tests.sh` runs; `compat-report.json` exists | This spec covers it |
| **M2** | Big-int | NaN-box + bigint overflow path lands as a unified value representation | Yes |
| **M3** | Import system + Tier-1 C modules | `import sys/io/os/unittest` works; `regrtest.py` itself runs | Yes |
| **M4** | First green tests | Tier-1 smoke list passes | No (test-driven) |
| **M5** | Object-model tests | `test_class`, `test_descr`, `test_exceptions`, `test_generators`, `test_with`, `test_decorators` pass | No |
| **M6** | 25% milestone | ≥25% of `Lib/test/` passing | No |
| **M7** | Tier-2 C modules + stdlib tests | `test_io`, `test_os`, `test_re`, `test_unittest`, `test_pickle`, `test_json`, `test_csv` pass | Yes |
| **M8** | 50% milestone | ≥50% passing | No |
| **M9** | Long tail | Remaining tests; full skip-list review | Yes |
| **M10** | Declared compatible | 100% minus accepted skips; tagged `v0.3.0-py3.0-compat` | No |
| **M11+** | Resume Pandas track | Phase 4 (cpyext), NumPy, Pandas, modern Python features | Per-phase specs at the time |

### Sequencing notes

- M1 can run in parallel with M0 (Phase 2). Vendoring is mechanical and doesn't conflict.
- M2 blocks M4 — many tests overflow i64.
- M3 is the longest single milestone; its sub-spec will likely decompose per-C-module.

## Risks

| Risk | Mitigation |
|---|---|
| Python 3.0 known bugs cause test failures we can't fix | Catalog in `python_3_0_bug` skip-list category; link CPython issue if found |
| `regrtest.py` itself needs more interpreter features than expected | M3 spec includes "make regrtest work" as a discrete sub-task before counting any tests |
| Crate API mismatch (e.g., `regex` semantics differ from CPython `_sre`) | Per-module Tier-2 spec calls out the API delta and patches the vendored stdlib if needed |
| Vendored tree size bloats the repo | `Lib/` is ~30 MB text; trivial against typical Rust project sizes |
| Big-int change destabilizes existing Phase 2 work | M2 lands as its own commit series with full regression check against current tests |
| AI-assisted code drifts from CPython semantics in subtle ways | `Lib/test/` itself is the regression suite — anything subtle eventually surfaces as a test failure |

## Open questions (deferred)

- Exact NaN-box layout for big-int promotion (M2 spec).
- How `_sre` adapts CPython's regex VM API to Rust's `regex` crate (M3 spec).
- Whether to handle 3.0's known bugs by patching the vendored stdlib or by skipping affected tests (M9 spec).
- Bytecode cache format and whether to implement at all (post-M10).
- Whether to expose the embedding API before M10 or after (leaning after).

## Immediate next step

Start M1: vendor `Lib/` and `Lib/test/`, add provenance and license files, scaffold the test harness scripts and reporting files even though no tests pass yet.
